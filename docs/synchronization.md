# Sincronización

`FootballAnalyticsPro-DailySync` ejecuta `scripts/sync_daily.py` cada día a las 08:00, hora local de Windows (Buenos Aires), con ventana de hoy −2 días a hoy +7 días. Los domingos agrega reconciliación completa de la temporada activa. La tarea requiere que Windows esté encendido y la sesión del usuario iniciada; `StartWhenAvailable` permite recuperar una ejecución perdida cuando Windows vuelve a estar disponible. Herramientas ejecuta el mismo servicio en un hilo de fondo al elegir Actualizar ahora. La acción diaria guarda su salida en `logs/scheduled_sync.log`.

`sync.orchestrator.run_sync` recorre las ocho competiciones y guarda cada una en su propia transacción. Un fallo por competición queda en `sync_run_items`; las demás siguen y el resultado global pasa a PARTIAL. El bootstrap carga catálogos, temporadas, equipos, calendario, resultados y snapshots de tablas. El script diario usa la ventana configurada y ejecuta una segunda reconciliación completa los domingos.

`repositories.match_sync.upsert_match` implementa persistencia idempotente por mapping de fuente, reconciliación conservadora de partidos, actualización de horario sin cambiar `match.id`, corrección de resultados de la misma fuente, conservación de valores conocidos ante NULL y registro de conflictos cuando una fuente de menor prioridad discrepa. Los registros POSTPONED y CANCELLED se actualizan como estados; el código no borra partidos.

El adaptador de football-data aplica un límite interno de 9 solicitudes por minuto. La capa HTTP aplica timeout connect/read, tres intentos para 429/5xx/errores de conexión y respeta `Retry-After` numérico o como fecha HTTP. OpenLigaDB consulta `getlastchangedate` por jornada y solo descarga las jornadas que muestran cambios durante daily/manual sync. Si el proveedor devuelve HTTP 404 para el marcador de una jornada aún no disponible, esa jornada se omite y se contabiliza como no modificada; no se marca la competición como fallida. Los marcadores válidos se guardan en `source_competition_seasons.metadata`; bootstrap y reconciliación completa descargan la temporada completa. OpenFootball se importa manualmente para histórico, nunca en daily sync. La base local ya pasó la verificación de conexión y la migración inicial.

Los scripts requieren una PostgreSQL configurada y `FOOTBALL_DATA_TOKEN` para la cobertura football-data. Sin ese token, las competiciones de esa fuente fallarán por separado y OpenLigaDB aún podrá continuar. Para reintentar una liga concreta se puede usar `python scripts/bootstrap.py --competitions UEL` o `python scripts/sync_daily.py --competitions UEL`.
