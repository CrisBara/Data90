# Sincronización

`FootballAnalyticsPro-DailySync` ejecuta `scripts/sync_daily.py` cada día a las 21:00, hora local de Windows (Buenos Aires), con ventana de hoy −2 días a hoy +7 días. Los domingos agrega reconciliación completa de la temporada activa. La tarea se configura para despertar el equipo si está suspendido y recuperar una ejecución perdida cuando Windows vuelve a estar disponible; requiere la sesión de Bara iniciada para disponer de las credenciales de las fuentes. Su límite de ejecución es de ocho horas. La acción diaria guarda su salida en `logs/scheduled_sync.log`.

El encabezado del ejecutable inicia la misma sincronización completa y muestra el último paso y las líneas recientes del proceso. Esta acción vuelve a consultar estadísticas individuales ya conocidas, se ejecuta en segundo plano y guarda su registro en `logs/manual_sync.log`. Un bloqueo de archivo compartido evita que la acción manual y la tarea diaria actualicen la base al mismo tiempo. Los feeds gratuitos respetan sus cuotas y pausas: si alcanzan una cuota diaria, conservan el avance y continúan en una ejecución posterior; no se fabrican datos cuando una fuente no los publica.

Después de reconciliar los planteles, el proceso consulta TheSportsDB y Wikidata para perfiles que aún tienen nacionalidad, posición o fecha de nacimiento vacías. Solo acepta coincidencias exactas no ambiguas, verifica compatibilidad de club cuando la fuente la informa y evita sobrescribir datos existentes. Wikidata también puede completar entrenadores faltantes. Ambos proveedores se limitan a metadatos biográficos; no se usan para estadísticas de temporada. TheSportsDB respeta su pausa de solicitudes y Wikidata conserva sus términos CC0.

La sincronización diaria repasa los últimos tres días de box scores en ESPN, actualiza planteles de Bundesliga, Ligue 1, Eredivisie, Champions League y Europa League desde sus rosters públicos, y actualiza las jornadas recientes de Promiedos; football-data.org u OpenLigaDB siguen actualizando el calendario primario. ESPN vincula perfiles existentes por club y nombre exactos, crea registros para los jugadores restantes de rosters de clubes verificados y solo guarda los campos biográficos publicados por la fuente. Las asociaciones dudosas se omiten; no se inventan estadísticas. Highlightly agrega box scores de jugadores de la temporada activa con un presupuesto local de 80 solicitudes diarias. Recorre una página por competición y enriquece perfiles incompletos bajo el mismo presupuesto; al alcanzar el límite, retoma en ejecuciones siguientes. Cada partido ya importado se omite de forma idempotente. La carga inicial de fixtures y resultados de Promiedos para las siete competiciones cubiertas se puede repetir con `python scripts/import_promiedos_match_fixtures.py`; la carga inicial de box scores ESPN, con `python scripts/import_espn_match_statistics.py`. Para adelantar la importación de Highlightly se puede ejecutar `python scripts/import_highlightly_match_statistics.py`; comparte el límite diario con la sincronización automática.

PitchAPI cubre como fuente secundaria los datos por partido de equipos y jugadores de Premier League, Bundesliga, Eredivisie, Champions League, Europa League, LaLiga, Ligue 1 y Serie A 2026/27, incluidos goles recibidos y vallas invictas publicados para arqueros. La importación inicial o una repetición completa se ejecuta con `python scripts/import_pitchapi_match_statistics.py`; es idempotente, y la actualización diaria solo vuelve a consultar partidos recientes o registros incompletos.

Para completar perfiles biográficos faltantes de futbolistas de la temporada activa de Eredivisie, Champions League y Europa League, se puede ejecutar `python scripts/sync_thesportsdb_profiles.py`. La fuente gratuita tiene límite de 30 solicitudes por minuto. Solo enlaza nombres exactos no ambiguos, preserva cualquier campo ya informado y registra el historial; no importa las estadísticas de temporadas antiguas como si fueran actuales. Esta consulta es manual y no aumenta la duración de la rutina diaria.


`sync.orchestrator.run_sync` recorre las ocho competiciones y guarda cada una en su propia transacción. Un fallo por competición queda en `sync_run_items`; las demás siguen y el resultado global pasa a PARTIAL. El bootstrap carga catálogos, temporadas, equipos, calendario, resultados y snapshots de tablas. El script diario usa la ventana configurada y ejecuta una segunda reconciliación completa los domingos.

`repositories.match_sync.upsert_match` implementa persistencia idempotente por mapping de fuente, reconciliación conservadora de partidos, actualización de horario sin cambiar `match.id`, corrección de resultados de la misma fuente, conservación de valores conocidos ante NULL y registro de conflictos cuando una fuente de menor prioridad discrepa. Los registros POSTPONED y CANCELLED se actualizan como estados; el código no borra partidos.

El adaptador de football-data aplica un límite interno de 9 solicitudes por minuto. La capa HTTP aplica timeout connect/read, tres intentos para 429/5xx/errores de conexión y respeta `Retry-After` numérico o como fecha HTTP. OpenLigaDB consulta `getlastchangedate` por jornada y solo descarga las jornadas que muestran cambios durante daily/manual sync. Si el proveedor devuelve HTTP 404 para el marcador de una jornada aún no disponible, esa jornada se omite y se contabiliza como no modificada; no se marca la competición como fallida. Los marcadores válidos se guardan en `source_competition_seasons.metadata`; bootstrap y reconciliación completa descargan la temporada completa. OpenFootball se importa manualmente para histórico, nunca en daily sync. La base local ya pasó la verificación de conexión y la migración inicial.

Los scripts requieren una PostgreSQL configurada y `FOOTBALL_DATA_TOKEN` para la cobertura football-data. `API_FOOTBALL_TOKEN` es una clave separada y habilita la carga de planteles, perfiles y estadísticas de temporada; la paginación se reanuda y el programa reserva un máximo local de 90 solicitudes diarias. Sin una de estas claves, sus fuentes correspondientes se omiten o fallan por separado y los demás proveedores continúan. Para reintentar una liga concreta se puede usar `python scripts/bootstrap.py --competitions UEL` o `python scripts/sync_daily.py --competitions UEL`.
